As of A07, **the major architectural decisions for Authopus v0.1.0 are settled**. The remaining questions concern security semantics, integration behavior, implementation details, and release readiness.

I would separate them into three categories.

## 1. Open design questions

These should be resolved before or during A08–A14.

| Priority | Question | Why it matters | Target task |
|---|---|---|---|
| P0 | Which OIDC providers must be supported initially? | Determines discovery, JWKS validation, issuer configuration and interoperability tests | A08 |
| P0 | How are trusted integrations authorized to assert agent identities? | Prevents an integration from impersonating arbitrary agents | A08 |
| P0 | What is the exact signed delegation token format? | Establishes claims, issuer, audience, expiry and signature requirements | A09 |
| P0 | How are delegation revocation and replay handled? | Determines whether an otherwise valid token remains usable after authority is withdrawn | A09 |
| P0 | How is principal authority represented in trusted claims? | Prevents delegation scopes from being mistaken for actual principal permissions | A09 |
| P0 | What are the complete A04 condition operators and type semantics? | Ensures deterministic policy evaluation across implementations | A10–A11 |
| P0 | How are policy conflicts resolved across multiple YAML documents? | Must preserve global deny precedence regardless of file ordering | A11 |
| P1 | What is the policy activation and rollback procedure? | Determines safe Git polling, validation and last-known-good behavior | A13 |

The first five are the most important unresolved security decisions.
